# Paid pilot offer worksheet

Status: proposed template, not a signed offer or revenue evidence.

- Opportunity, technical owner, budget owner and decision date:
- One use case / integration / supported environment:
- Start, end and delivery checkpoints:
- Deliverables: working component, reproduction bundle, evaluation report,
  integration and recovery documentation:
- Acceptance: agreed tests and numeric thresholds from [EVALUATION.md](EVALUATION.md):
- Customer contribution: named engineer, workload and hardware/interface access:
- Fixed fee, currency, invoicing and payment milestones:
- Scope assumptions, support hours and exclusions:
- Change process: document additional cost/time before accepting extra scope:
- Ownership, licensing and confidentiality terms for review by both parties:
- Next step after acceptance: production evaluation or annual support agreement:

Price from delivery cost, scope and buyer value; the repository supplies no
validated price. Aether's public core is MIT OR Apache-2.0. State the paid value
explicitly: supported release, integration work, validation tooling or verified
hardware support. Do not imply exclusive ownership of the public core.

Track proposed, signed, invoiced and paid separately with private evidence.
An unpaid collaboration can validate feasibility; it does not establish
willingness to pay. Compare the second pilot's shared code/tests/docs and
integration hours with the first to test whether delivery can repeat.
